## Problem

Decision time is dominated by per-world setup and opponent-model work that barely
scales with the node budget. Doubling `k` at fixed nodes roughly doubles wall time
(+9% when doubling nodes at fixed `k=4` in quarter-scale self-play).

**Work that does not depend on hidden cards:** root candidate filter, `deal=block`
shuffle stream, order-net / leaf encoding of the **observed** state, consensus lethal
on shared structure, `tkill`/`tkroll` on roots.

**Per-world / hidden-dependent:** `determinize_block`, each world's search tree, TT
entries keyed on determinized states, opponent reply under `Info::Draws` / leaf masks.

## Changes (bit-identical)

### `apply_known_legal` on proven-legal hot paths

`apply()` rebuilds the full legal list on every ply; search already holds actions
taken from `legal_actions`. Hot paths now use `try_apply_legal` → `apply_known_legal`
(same semantics as `d07388f` / prior perf series, extended to world roots, greedy
picks, opponent reply expansion, lethal face lines, evolve/ward prefixes, `one_ply`).

**Why identical:** `apply_known_legal` is `debug_assert!(legal.contains(action))` in
debug only; release calls the same `apply_after_check` as a successful `apply`.

**Measured gain:** ~0.5–1.5% on review 12-pack; ~2–4% on 52-case harness (see artifact
deltas vs pre-branch timings).

### Left out (behaviour or threading)

| Idea | Est. gain | Why skipped |
|------|-----------|-------------|
| Per-decision leaf `encode` cache | 5–15% on net-heavy leaves | Needs `Sync` cache with `threads>1` served spec; not wired without decision-scoped `Arc<Mutex<…>>` + careful float identity |
| Parallel world search default | ~linear in threads | Intentionally `threads=1` for this brief; changes job ordering under explain |
| Reorder FP summation in `root_agg` | small | Would break `h0_exact` pins |
