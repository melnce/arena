# H0 search speed — November 2026

## Machine

- **CPU:** Intel(R) Xeon(R) Processor (`nproc=4`)
- **Build:** `cargo test --release -p arena-engine`
- **Baseline parent commit:** `edde4b5`

## Problem

Decision time is dominated by opponent-model work (`oopen`, `opp_lethal`) and net
leaf/order encoding inside each world's own search. The main bot search is a large
fraction of wall time but most **charged nodes** sit on the opponent side.

## Duplicate work within one decision (`h0-prof`)

| Kind | sweep repeat rate | served repeat rate |
|------|-------------------|-------------------|
| leaf_value / leaf_encode | 37.0% | 37.6% |
| opp_lethal | 29.9% | 30.1% |
| oopen | 29.3% | 29.7% |

Probes key on `search_key_id(state)` XOR seat shift (same state hash across worlds).

**Cached (bit-identical):** per-decision **leaf net output** keyed on
`(search_key_id, me, value net ptr, clip bits)`. Stored as `f32::to_bits`.
Thread-local bind + `Arc<Mutex<…>>` for `threads>1`.

**Not cached:** `opp_lethal` / `oopen` — repeats are frequent but results depend on
`line` cycle keys, remaining node cap at entry, and PV tracking; a hit would need to
replay exact node charges and side effects. `order_net` has no dup probe but is hot;
caching would need a separate key including order-net identity.

## Bit-identical changes

### `apply_known_legal` on proven-legal hot paths

Skip redundant `legal_actions` where the action is already from a legal list.

### Per-decision leaf value cache

Clears each `choose`; TLS bind for parallel worlds.
